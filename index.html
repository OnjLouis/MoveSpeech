Move Speech Help

Speech fixes for Ableton Move. Version 1.0.

Before Installing

You need Ableton Move, an internet connection and a root SSH shell on the device. This installer does not enable SSH or bypass its authentication. Keep Move connected to power and stop playback or recording before installing. Move normally saves sets automatically.

Move Speech is an unofficial modification, not an Ableton product. It does not replace Move's voice engine or install Schwung. It requires Move's existing Python 3, OpenSSL and system utilities; no compiler or extra package installation is needed.

Install

Run this command in Move's root SSH shell, not in your computer's ordinary terminal:

python3 -E -s -B -c 'import urllib.request;exec(urllib.request.urlopen("https://raw.githubusercontent.com/OnjLouis/MoveSpeech/main/bootstrap.py",timeout=30).read())'

The installer explains what it found and asks before restarting Move. It downloads a signed package over verified HTTPS, checks compatibility and constructs the patched executable on your own device. It then enables the fixes at startup. Stock Move and recognised Schwung installations are supported; existing voice settings are preserved.

Wait for the completion message. After the restart, open Sampling and turn the wheel to check speech, then try Slice and the sample controls.

For an unattended install, add --yes after the command's closing single quote. This approves the restart without asking. Otherwise an unattended command stops rather than waiting for an answer.

Using Speech

The fixes send text through Move's normal screen-reader path. Open Move's screen-reader page and complete its normal pairing if requested. Use your computer or phone's screen reader as usual.

If you already use on-device speech through Schwung, the same restored text is available to it. You do not need Schwung for browser-based speech. Move Speech does not install voices, alter voice licences or change your chosen speech settings.

  • Sampling: menu headings, source, gain, monitoring and recording state.
  • Slice: slice count and the relevant region controls.
  • Sample controls: start and end values when a sample is loaded, including knob 2 and Shift with knob 5.
  • Step velocity: hold a step and turn the volume control to hear its changing velocity value.

Other controls using the repaired display paths can also benefit. Audio-track Tempo, Start and Input Gain, and drum-pad Volume have been reported working. This does not mean every silent screen or control is fixed.

Firmware Compatibility and Updates

Firmware profiles
FirmwareVerification
2.1.5b2Speech confirmed on a physical Move.
2.1.5b1 and 2.1.1Offline compatibility checks only; a physical-device trial is still needed.

Exact executable and startup-script checks must pass. A matching version number alone is not sufficient. An unfamiliar firmware or independently modified startup script is left unchanged rather than patched speculatively.

Uninstall Move Speech before installing an official firmware update, so its temporary executable mount cannot interfere with the updater. After updating Move's firmware, run the same install command again. It fetches the current signed compatibility information. The installer uses Move's native executable even when Schwung provides the launcher, so you do not need a separate stock or Schwung command.

Future firmware is not automatically guaranteed to work. If its profile is unavailable, wait for a Move Speech update. If the startup guard encounters a changed native executable, it declines to apply the old patch and lets unmodified Move start.

Check or Remove

Add --check after the install command to verify compatibility and build the patch in memory without restarting Move or changing its startup. Add --status to display the installed state.

Add --uninstall to restore unmodified Move and remove our startup additions. A brief restart is required. Voice settings, sets and other startup changes are preserved. Removal can work after an unrecognised firmware update because it does not build a new patch, but unfamiliar executable layouts or changed speech startup blocks are refused safely. The installer retains its small support files, bounded logs and rollback archive for diagnosis and reinstalling.

When already installed, these offline commands are also available:

python3 -E -s -B /data/onj-move-accessibility/install.py --status
python3 -E -s -B /data/onj-move-accessibility/install.py --check
python3 -E -s -B /data/onj-move-accessibility/install.py --uninstall

Recovery and Storage

The original native executable is not overwritten. A separate patched copy lives on Move's data partition, with a reversible file mount selecting it. Allow at least 100 MiB of free data storage. The installer does not copy a large executable onto the small system partition.

Ordinary installation failures trigger restoration of the previous startup and managed files. Once the restart operation has been handed to its worker, it can finish if the SSH connection drops. This is not a guarantee against power loss, storage failure or every firmware change: keep power connected.

Logs are kept in /data/onj-move-accessibility as install.log, install.previous.log, startup.log and startup.previous.log. The latest operation is recorded in operation.json. No background patch daemon is left running.

If installation fails, preserve the error and these logs before retrying. Do not manually delete or replace Move's firmware files. If an independently changed startup or unknown executable mount is reported, the installer refuses to overwrite it.
